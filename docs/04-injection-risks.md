# 注入风险与缓解

本文档完整列出采用进程注入方案的代价。**使用前请确认已理解全部内容。**

## A. 会导致宿主崩溃的风险

### A1. 异常穿透

被注入的代码与 PotPlayer 共进程。访问违例、未捕获异常、栈溢出都会终止整个播放器进程。

**缓解**：回调内不抛异常；每一项可能越界的读取（PE 结构、thunk 数组、名称 RVA）都必须做显式边界校验——本项目用 MinGW 构建，没有 MSVC 的 `__try/__except` 可用，所以**校验必须前置**，不能指望异常兜底。另外安装向量化异常处理器，崩溃时至少能在日志里留下异常码与出错地址所属模块。这仍无法防止堆破坏。

### A2. 堆破坏

回调内分配/释放对象、缓冲区越界会污染宿主堆，表现为随机崩溃、播到第 N 首才崩，极难复现。

**缓解**：回调内使用固定大小栈缓冲，不做容器操作与动态分配。

### A3. 死锁

挂接点可能持有系统内部锁。若回调内再次调用 SMTC 方法或等待被对方线程持有的锁，将直接死锁。

**缓解**：回调内只做参数拷贝与标志位置位，耗时操作移交自有线程；绝不在 hook 内同步等待。

### A4. 悬空 hook

若 DLL 被卸载而 hook 仍在，下一次调用将跳转到已释放内存。

**缓解**：注入后永不卸载；或在卸载前完整恢复全部 hook。

## B. 安全软件与系统机制

### B1. 杀软 / EDR 误报

"远程线程注入 + 用户态 API 挂接"是恶意软件的典型行为组合，可能被拦截、报毒、隔离文件。

**缓解**：为注入器与 DLL 添加排除项；不注册为常驻服务。

### B2. 系统进程缓解措施

若目标进程启用了 **ACG（Arbitrary Code Guard）** 或 **CIG（Code Integrity Guard）**，注入将直接失败。ACG 一旦启用，任何动态代码执行都会被禁止。

**缓解**：使用 `Get-ProcessMitigation -Name PotPlayerMini64.exe` 检查状态。关闭这些缓解会降低系统安全性，需自行权衡。

### B3. 签名与 SmartScreen

自编译的注入器无签名，首次运行会被 SmartScreen 拦截。

**缓解**：个人自用可忽略。

## C. 维护性风险

### C1. 版本兼容

PotPlayer 更新可能改变 `MediaDB64.dll` 的实现。

**缓解**：优先挂接 COM vtable（接口方法顺序由 Windows SDK 固定）与导入表，避免硬编码偏移。32 位 / 64 位需分别编译。

### C2. 注入时机

晚注入可能错过目标进程创建 SMTC 对象的时机。

**缓解**：见 [`02-architecture.md`](02-architecture.md) 中关于 `GetForWindow` 的说明。

### C3. 与宿主抢写

补写的字段可能被宿主随后的写入覆盖，出现字段闪回。

**缓解**：挂接 `Update()`，严格保证补写发生在宿主写入之后。

### C4. 无法即时停用

已注入的代码只能通过重启目标进程清除。

**缓解**：提供开关文件与"只读观察模式"。

### C5. 调试成本

进程内崩溃通常不产生 dump。

**缓解**：自行安装未处理异常过滤器并生成 minidump。

### C6. 性能

被挂接的 API 可能是高频调用（如 `CreateFileW`）。

**缓解**：回调内先做最廉价的判断（扩展名比对），不命中立即返回。

## D. 边界与合规

### D1. 非官方支持

本项目不属于 PotPlayer 官方扩展，与 Kakao Corp. 无关，不受其支持。

### D2. 分发建议

建议仅在自有设备使用。分发预编译注入器可能违反软件用户协议，且极易被判定为恶意软件。仓库仅发布源码。

## E. 影响范围（唯一的正面因素）

由于采用**进程内挂接**而非全局 hook 或驱动方案，影响被严格限制在 PotPlayer 单一进程内。系统其他程序、其他播放器完全不受影响。
